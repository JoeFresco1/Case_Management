## 1. OpenAPI schema generation

- **O-01 (High) — `POST /cases/{id}/transitions` has no `response_model`.** `backend/app/interfaces/http/routers/cases.py:578-596` declares `summary` + `responses` but no `response_model=ExecuteTransitionResponse`, even though the handler returns that type. The OpenAPI document falls back to an undocumented schema for the primary P02 mutation. Add `response_model=ExecuteTransitionResponse` (the class already exists in `schemas/cases.py:226`).
- **O-02 (High) — `GET /events/catalog` has no response model.** `backend/app/interfaces/http/routers/events.py:21-22` returns `dict[str, Any]`. No schema, no example — `openapi-typescript` generates `unknown`. Define a `EventCatalogResponse` schema.
- **O-03 (High) — `GET /health` returns `dict[str, object]`.** `backend/app/interfaces/http/routers/health.py:100-101` has no `response_model`. The adapter-inventory contract (`adapters.db/store/bus/idp/...`, `synthetic_environment`) that the frontend banner depends on is invisible to codegen. Define a `HealthResponse` schema (AGENTS.md §17.1 explicitly requires frontend types be generated, never hand-typed).
- **O-04 (High) — three divergent `Page[T]` definitions.** `backend/app/interfaces/http/pagination.py:46`, `backend/app/interfaces/http/schemas/cases.py:179`, `backend/app/interfaces/http/schemas/forms.py:103` each declare their own generic `Page`. `tasks.py:38` imports `Page` from `schemas/cases` (wrong pillar), `search.py:48` imports only `MAX_LIMIT` from `pagination`. Same shape today, but three owners for `DEFAULT_LIMIT`/`ge`/`le` guarantees drift. Canonicalise on `pagination.Page` and delete the schema-local copies (or re-export).
- **O-05 (High) — error responses are description-only; `ErrorResponse` never appears in OpenAPI.** Every router's `responses={...}` maps status codes to `{"description": ...}` strings (e.g. `cases.py:262-265`, `tasks.py:77-88`, `audit.py:135-139`). No route declares `model=ErrorResponse` / `content` schema, so generated clients have no typed error path despite AGENTS.md R7 requiring `ErrorResponse{code,message,details,correlation_id}` on every endpoint.
- **O-06 (Medium) — binary download is schema-less.** `documents.py:90-99` uses `response_class=Response` with no `content` media-type declaration. Expected (`application/octet-stream` + `Content-Disposition`) is only visible in code (`documents.py:132-136`). Declare the octet-stream response in OpenAPI.
- **O-07 (Medium) — unpaginated list returns bare `list[...]`.** `documents.py:444-451` (`GET /documents/{id}/versions` → `response_model=list[DocumentVersionResponse]`) and `admin_workflows.py:209` (`response_model=list[WorkflowSummaryResponse]`) bypass the `Page[T]` envelope required by AGENTS.md §17.1 ("every list endpoint paginates"). Either paginate or record an explicit exception with rationale (as `events.py:24-30` correctly does for the bounded catalog).
- **O-08 (Medium) — `POST /audit/signed-batches` list hardcodes `next_cursor=None`.** `audit.py:670-674` always reports last-page even though the store could grow. Same pattern in `tasks.py:228`. A client that loops on `next_cursor` terminates correctly by accident, but a client that checks `len(items)==limit` as the cases router suggests will disagree. Return a real cursor or document "unbounded, single page" explicitly.
- **O-09 (Low) — `idempotency-replay: true` response header is undocumented.** `idempotency.py:188` sets it on every replay, but no router's `responses` or OpenAPI `headers` section mentions it. Generated clients cannot discover replay vs fresh responses.

## 2. Error response format

Contract: `ErrorResponse{code,message,details,correlation_id}` with `exclude_none=True` (`errors.py:25-48`); `domain_error_handler` maps `ValidationFailed→422`, `NotFound→404`, `Forbidden→403`, `Conflict/UnsupportedTransition→409`, else `internal_error→500` without leaking internals (`errors.py:58-101`); `RequestValidationError→422 validation_failed` (`main.py:304-315`).

- **E-01 (Critical) — most `HTTPException(detail=...)` sites do not emit `ErrorResponse`.** Two shapes in the wild:
  - (a) bare string: `cases.py:191` (`detail="Idempotency-Key header is required"`), `cases.py:360/428/435/472`, `tasks.py:106`, `documents.py:184/358/571/674`. FastAPI serialises this as `{"detail": "<string>"}` — no `code`, no `correlation_id`.
  - (b) dict-in-detail: `audit.py:192/207/238/327/353/427/521/564/738`, `documents.py:128/203/241/290/377`, `capture.py:191/331`, `webhooks.py:336/592`. FastAPI serialises this as `{"detail": {"code": ..., "message": ...}}` — nested one level too deep, still no top-level `code`/`correlation_id`.
  - Only `errors.py:error_response` and the `main.py` validation handler emit the true top-level shape. Any client coded against `ErrorResponse` fails to parse the majority of 400/404/409/422/503 bodies.
- **E-02 (High) — `edit_case` 409 does not carry the current token despite the comment promising it.** `cases.py:459-479` comment says "we attach the current `version_token` via `details` so the client does not have to do a second GET", but the code raises `HTTPException(detail=str(exc), headers={ETag, X-Current-Version-Token})` — token in headers only, body is a plain string (see E-01a). FR-003 acceptance ("body carries the current token") is not met on the wire.
- **E-03 (High) — `domain_error_handler` covers 5 of N domain errors.** `errors.py:58-101` handles `ValidationFailed/NotFound/Forbidden/Conflict/UnsupportedTransition`. `DependencyUnavailable` (`documents.py:124-129` handles manually — good), `DocumentLocked` (handled per-route — good), but any future/new domain error (e.g. `HoldNotPresent`, quota, policy) falls through to `internal_error→500` with the real message swallowed (`errors.py:96-101`). That is safe but misclassifies client errors (e.g. hold-absent → 500 instead of 409/404). Audit the taxonomy or add explicit arms.
- **E-04 (Medium) — middleware `_error` shape drifts from `error_response`.** `idempotency.py:59-69` emits `{"code","message","details": None,"correlation_id"}` with `details: None` present, while `error_response` uses `exclude_none=True` (key absent). Strict clients doing exact-shape match or snapshot tests see two variants of the same 400/409/503.
- **E-05 (Medium) — `correlation_id` is `""`, not absent, on unauthenticated/middleware paths.** `_correlation_id` returns `""` when no context exists (`errors.py:51-55`, `idempotency.py:210-215`); the fixture test even asserts `body["correlation_id"] == ""` (`test_error_model.py:187`). The schema says `str | None = None`. Empty-string vs missing vs real id are three states for "unknown" — pick one (recommend: omit when unknown, consistent with `exclude_none`).
- **E-06 (Medium) — test fixture does not test the real validation handler.** `tests/interfaces/test_error_model.py:64-74` re-implements a lookalike handler (`correlation_id: ""` hardcoded, no `ErrorResponse` model) instead of importing the `main.py` handler. The test passes while the shipped handler could drift. Import or factor the handler.
- **E-07 (Low) — `details` key naming is inconsistent.** `errors.py:66` uses `{"field": ...}` (singular), audit dict-details use `{"field": ...}` too, but validation handler uses `{"errors": [...]}` (plural list). Document the two shapes (`field` for domain validation, `errors` for Pydantic validation) in the OpenAPI description so clients branch correctly.

## 3. Pagination implementation

Contract: `Page[T]{items,next_cursor,limit}`, default 50 max 200 (`pagination.py:27-28`, AGENTS.md §17.1).

- **P-01 (High) — `build_page`/`normalize_limit` are dead code.** No router imports them (only `search.py:48` imports `MAX_LIMIT`). `cases.py:385`, `forms.py:236/317`, `tasks.py:228` construct `Page(...)` directly. The "factory re-applies clamp so an endpoint that forgets to clamp cannot ship an out-of-range page" guarantee (`pagination.py:59-64` docstring) never executes. Either route all endpoints through `build_page` or delete it — a tested-but-unused safety net is worse than none (the passing `test_pagination.py` suite tests a function nothing calls).
- **P-02 (High) — `next_cursor` is `"<offset>:<limit>"`, not opaque, and unusable.** `cases.py:381-383`, `forms.py:232-236/313-317` encode `f"{offset+limit}:{limit}"`, but neither endpoint accepts a `cursor` query param — only `limit`+`offset`. The client cannot redeem the cursor it is given; it must parse the opaque string (contradicting "opaque"). The comment (`cases.py:376-380`) admits a real cursor "lands with FM-031" — until then either accept `cursor` or stop emitting fake cursors.
- **P-03 (High) — `GET /tasks` never paginates.** `tasks.py:228` hardcodes `next_cursor=None` and returns whatever the use case returned. No `len==limit` check (unlike cases/forms), so a full page is indistinguishable from last page — silent truncation for large queues. Same for `audit.py:672` (signed batches).
- **P-04 (Medium) — limit ceiling is copy-pasted, not shared.** `cases.py:338`, `tasks.py:198`, `audit.py:147/302/499` hardcode `Query(ge=1, le=200)`; only `search.py:156` uses the `MAX_LIMIT` constant. A future ceiling change requires touching N files. Use `Query(ge=1, le=MAX_LIMIT)` + shared default everywhere.
- **P-05 (Medium) — parallel pagination envelopes.** `TimelinePage`, `AccessDecisionPage`, `SignedBatchPage`, `ExportBatchResponse{items,next_cursor,limit,rows_in_batch}` (`schemas/audit.py`) duplicate `Page[T]` with extra/different fields. AGENTS.md §17.1 says "every list endpoint paginates through `Page[T]`". If the audit shapes are deliberate (cursor encoder, row counts), document the deviation in one place; otherwise unify.
- **P-06 (Low) — `Page.limit` echoes the request, not necessarily the effective window.** `cases.py:385` passes raw `limit` (already Query-clamped, so fine today), but if clamping ever moves to `normalize_limit` (silent cap vs 422), the echo must be the post-clamp value. `build_page` already does this — another reason to adopt P-01.

## 4. Authentication / authorization middleware

Stack: `CorrelationMiddleware` (outer, runs first — `main.py:300`) → `IdempotencyMiddleware` (`main.py:298`) → `get_current_user` per-route dependency (`deps.py:94-121`); authz inside use cases via `authorize(Action...)`.

- **A-01 (Medium) — `GET /events/catalog` is the only unauthenticated business endpoint.** `events.py:14-22` has no `Depends(get_current_user)`. Probably intentional (public discovery), but it is the sole exception among 30+ routers and imports `app.domain.events` directly into the interface layer (layering smell — routers should depend on application only). Record the decision (public vs oversight) in an ADR; if public, note rate-limit posture.
- **A-02 (Low) — `GET /health` is unauthenticated by design but exposes posture.** `health.py:101` takes only `settings`. It leaks `app_env`, adapter labels, `tenant_listener_enabled`, `outbox_dispatcher_enabled`. Acceptable for local dev, but confirm the prod posture (auth vs redacted fields) before Azure — currently undocumented.
- **A-03 (High) — `X-Dev-Tenant` is enforced only inside the idempotency middleware.** `_authenticate_request` (`idempotency.py:192-207`) rejects tenant-header mismatch with 401, but the per-route `get_current_user` (`deps.py:94-121`) never reads `X-Dev-Tenant` at all — it returns the registry tenant for `X-Dev-User`. Every GET (which bypasses the middleware per `idempotency.py:82-85`) and every non-`/api/v1/` path ignores the tenant header entirely. Either enforce in `get_current_user` (single choke point) or document that the header is advisory/replay-only. Current state: two auth paths with different checks.
- **A-04 (Medium) — double authentication per mutation.** Middleware authenticates and stashes `request.state.user` (`idempotency.py:103`), then the route re-authenticates via `Depends(get_current_user)`. The stashed user is never consumed. Besides wasted registry lookups, a `dependency_overrides` change between the two resolutions (tests) can authenticate as two different users in one request (replay check as A, mutation as B). Consume `request.state.user` in routes or remove the stash.
- **A-05 (Medium) — `LocalHeaderIdentityProvider` is dead code.** `deps.py:61-83` defines the class, but `get_current_user` reads the `_LOCAL_USERS` dict directly (`deps.py:109`) and the class has zero instantiations. The "local adapter" seam the docs point at is not the code that runs. Wire it or delete it so the Entra seam (`deps.py:3-5` seam comment) has one obvious replacement point.
- **A-06 (Medium) — CORS is maximally permissive.** `main.py:291-297`: `allow_origins=settings.cors_origins, allow_credentials=True, allow_methods=["*"], allow_headers=["*"]`. If `cors_origins` defaults to `["*"]` with credentials allowed, browsers will reject it at best and it invites CSRF-adjacent confusion at worst. Verify the default in `config.py`; credentialed wildcard CORS should fail closed.
- **A-07 (Medium) — mutation authz coverage is uneven at the HTTP layer.** `POST /cases/{id}/participants`, `PATCH/DELETE /participants/{id}` (`participants.py:45-119`), `POST /audit/{id}/correction` (`audit.py:384-398`) carry no `Idempotency-Key` or `If-Match` requirement and no documented concurrency story, unlike cases/tasks/documents. Concurrent double-submit can double-append participants/corrections. Extend the mutation contract or document why these are exempt.
- **A-08 (Low) — `GET /documents/{id}/content` commits a transaction.** `documents.py:131` calls `await db.commit()` after a read (audit row for download — intentional), but the route is a GET that the idempotency middleware deliberately skips. A download that fails after the audit append but before byte-streaming leaves a "downloaded" audit row with no delivery. Confirm the ordering (stream-then-commit vs commit-then-stream) is intentional.

## 5. Idempotency-key handling

Stack: `IdempotencyMiddleware` reserves/finalizes per `(tenant,key,request_hash)` in the same DB transaction (`idempotency.py:72-172`); routers re-check presence and raise 400 (`cases.py:188`, `tasks.py:103`, `documents.py:180/354/568/671`, etc.).

- **I-01 (Medium) — `scope_paths` has a trailing-slash trap.** `main.py:298` registers `scope_paths=("/api/v1/",)` while the middleware default is `("/api/v1",)` (`idempotency.py:78`). Matching is `path.startswith(prefix)`. Today `/api/v1/health` matches the registered prefix, but any future mount at exactly `/api/v1` (no trailing slash) or a test that constructs the middleware with defaults gets different coverage. Normalise (strip trailing slash before compare) and add a regression test for both spellings.
- **I-02 (High) — only `POST` is protected; PATCH/PUT/DELETE are not.** `idempotency.py:87-92`: missing key → 400 only when `method == "POST"`; other methods fall through to `call_next`. `PATCH /cases/{id}` (`cases.py:411-420`, If-Match only), `PATCH/DELETE /participants/*`, `PUT/DELETE` across admin/queue/channel routers therefore have no replay protection despite AGENTS.md §10 ("idempotency on mutations"). Decide: extend middleware to all non-idempotent-safe methods or state that PATCH relies solely on `If-Match` (and then enforce `Idempotency-Key` on the remaining DELETEs/PUTs).
- **I-03 (High) — router-level key checks are unreachable dead code for covered POSTs.** Middleware runs before routing and already 400s a missing key on POST (`idempotency.py:88-91` returns `_error`, never calls `call_next`). The identical checks in `cases.py:188`, `tasks.py:103`, `documents.py:180`, `forms.py:123`, `capture.py:188/328`, `webhooks.py:332/588` can never fire in production — and when they do fire (middleware disabled in tests, direct handler invocation), they raise `HTTPException(detail="<string>")`, a different envelope from the middleware's `ErrorResponse` shape (see E-01). Keep one enforcement point (middleware) and delete or rewire the router checks to it.
- **I-04 (Critical) — multipart uploads can never replay.** `_mutate` hashes `await request.body()` (`idempotency.py:115-118`); for `multipart/form-data` the raw body embeds a random boundary string, so two identical file retries hash differently (`canonical_request_hash` JSON parse fails → `raw_sha256` of boundary-laden bytes, `idempotency.py:48-56`). `upload_document`, `add_document_version`, `redact_document` (`documents.py:161-344/548-...`) advertise idempotent retry but a transport retry generates a fresh boundary → `request_hash` mismatch → 409 "belongs to another request" instead of replay. Hash the semantic payload (filename + bytes + fields), not the wire encoding — or exempt multipart with a documented alternative (content-SHA header).
- **I-05 (Medium) — response buffering breaks streaming and bloats memory.** `idempotency.py:152` does `b"".join([chunk async for chunk in response.body_iterator])` for every keyed mutation. Correct for JSON, but any future large/file response under a key loads fully into memory twice (buffer + base64 in `finalize`, `idempotency.py:154-167`). Cap buffered size or skip buffering for non-JSON content types.
- **I-06 (Medium) — length cap lives only in middleware.** `idempotency.py:93-94` rejects keys >128 chars; router checks (`cases.py:188` et al.) only test emptiness. Overlong keys produce 400 via middleware in prod but pass router unit tests that call handlers directly. Share one `validate_key` helper.
- **I-07 (Medium) — non-2xx outcomes are not stored, forcing key rotation on fix-and-retry.** `idempotency.py:153` finalizes only on `200<=status<300`. A 422 validation failure leaves the reservation un-finalized (provider-dependent: row either rolls back or stays reserved without response). Either way the client that fixes the payload and retries with the same key gets 409 request-hash-mismatch (I-path, `idempotency.py:141-144`) and must mint a fresh key. Document the "one key per corrected attempt" rule — currently undiscoverable.
- **I-08 (Low) — replayed headers include stale `content-length`/`etag`.** `idempotency.py:159-165` persists all raw headers except `x-correlation-id`/`idempotency-replay` and replays them verbatim (`_replay`, `idempotency.py:175-189`). If the underlying resource changed between original and replay window (it shouldn't — same key+hash — but clock/date headers do), the replayed `date`/`content-length` can disagree with the actual bytes. Strip volatile headers (`date`, `content-length` recomputed by Starlette) on replay.
- **I-09 (Low) — `GET /tasks` documents idempotency it doesn't need.** `tasks.py:18-20` docstring discusses `IdempotencyMiddleware` + domain `Task.complete` idempotence on the list endpoint. Harmless but confusing — the list is a GET and bypasses the middleware entirely. Trim the docstring to the complete endpoint.

## Suggested triage order (not fixes — ordering only)

1. **Wire-contract breaks:** E-01/E-06 (unify on `ErrorResponse` — one `http_exception_handler` that wraps all `HTTPException.detail` into the envelope), E-02 (honor the 409-token-in-body promise), I-04 (multipart hash).
2. **Coverage gaps:** I-02 (PATCH/PUT/DELETE idempotency policy), A-03 (single `X-Dev-Tenant` choke point), P-01+P-02 (adopt `build_page` or delete; make cursors real or remove).
3. **OpenAPI honesty:** O-04 (one `Page`), O-01…O-03 (missing response models), O-05 (declare error model), O-07 (paginate or exempt explicitly).
4. **Hardening:** A-06 (CORS default), I-01 (scope prefix normalisation), I-07 (document key-rotation rule), P-04 (shared limit constant).
5. **Hygiene:** A-05 (dead `LocalHeaderIdentityProvider`), I-03/I-06 (single key-validation helper), E-04/E-05 (details-None + empty-cid shape), A-01/A-02 (record public-endpoint decisions).
