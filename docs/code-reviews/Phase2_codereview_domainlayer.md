## 1. Purity — framework / ORM imports (PASS)

Automated scan of actual `from`/`import` statements across `backend/app/domain/*.py` shows **zero** imports of `fastapi`, `sqlalchemy`, `pydantic`, `httpx`, `starlette`, `app.application`, `app.infrastructure`, or `app.interfaces`. All hits for those strings are prose inside docstrings/comments (e.g. `backend/app/domain/ports.py:17`, `backend/app/domain/role.py:7`, `backend/app/domain/session.py:3`, `backend/app/domain/outbound_webhook.py:29`), which is documentation, not a dependency. Cross-module imports are strictly `app.domain.*` → `app.domain.*` (`backend/app/domain/ports.py:40-69` re-exports aggregate types, which is the documented direction).

Two purity-adjacent findings (not import violations, but state/I/O-adjacent constructs living in the "pure" layer):

- **F-01 (Medium) — mutable process-global registry + lock live in the domain.** `backend/app/domain/extension.py:56` imports `threading.RLock` and `backend/app/domain/extension.py:549` instantiates a module-level `_REGISTRY` singleton mutated by `ExtensionRegistry.install`. A lock and a mutable global are defensible, but they contradict the layer's "pure domain: no I/O, no state" posture claimed by sibling modules, and they make domain state process-global (test pollution / multi-tenant bleed risk if the singleton is ever tenant-scoped). Consider documenting why the registry lives in domain rather than application, or moving the singleton accessor behind the application seam.
- **F-02 (Medium) — a concrete repository implementation lives in the domain.** `backend/app/domain/reference_format.py:339` defines `InMemoryReferenceFormatRepository` (a `@dataclass` with a mutable `_by_tenant` dict) inside the domain layer. Per AGENTS.md R10, infrastructure implements ports; adapters — even in-memory ones — do not belong in `app/domain`. The `Protocol` (`backend/app/domain/reference_format.py:314`) belongs here; the adapter should move to infrastructure or test fakes.

## 2. Tenant isolation (CONDITIONAL PASS — findings T-01…T-04)

Credit: every *read* method on every repository Protocol takes `tenant_id: UUID` first and documents `WHERE tenant_id = :tenant_id` plus `None`-on-cross-tenant semantics (indistinguishability per Constitution V). This is consistent across `CaseRepository`, `DocumentRepository`, `AuditEventStore`, `SlaClockRepository`, `LegalHoldRepository`, capture/quarantine ports, retention/disposition ports, and the search ports.

- **T-01 (High) — write methods violate the stated "every method takes `tenant_id` first" contract.** The module docstring (`backend/app/domain/ports.py:9-11`) claims *every* repository method takes explicit `tenant_id` as its first query-scoping argument. Counter-examples: `CaseRepository.add/update` (`backend/app/domain/ports.py:102-105`), `CaseTypeRepository.add` (`backend/app/domain/ports.py:161`), `CaseTypeVersionRepository.add` (`backend/app/domain/ports.py:176`), `DocumentRepository.add_document_and_version/add_version/save_locked/add_redaction` (`backend/app/domain/ports.py:191-262`), `RoleRepository.add` (`backend/app/domain/ports.py:1171`), `SlaClockRepository.add/update` (`backend/app/domain/ports.py:809-827`), `SessionRepository.add/save` (`backend/app/domain/ports.py:1239-1251`), `QueueRepository.add/update` (`backend/app/domain/ports.py:569-576`), `TaskRepository.add/update` (`backend/app/domain/ports.py:615-618`), `WorkflowInstanceRepository.add/update` (`backend/app/domain/ports.py:716-731`). These rely on the aggregate's embedded `tenant_id`, which is a reasonable design — but then the docstring contract is false, and nothing at the type level stops an implementation from persisting an aggregate whose `tenant_id` disagrees with the caller's tenant. Either amend the contract ("writes scope via the aggregate's `tenant_id`; reads scope via parameter") and add a cross-check recommendation for adapters, or add `tenant_id` to the write signatures.
- **T-02 (High) — `TenantScoped` enforcement claim is overstated.** `backend/app/domain/ports.py:79-87` defines an empty, `runtime_checkable` marker Protocol with no members. An empty runtime-checkable protocol matches *every* object at runtime and enforces nothing at static-check time. The docstring's three-layer enforcement story (type-level / listener / test-level) therefore rests entirely on layers 2–3. This is not a security hole by itself, but reviewers should not treat `TenantScoped` subclassing as evidence of scoping. Consider a protocol with at least one member, a `mypy` plugin check, or toning down the docstring.
- **T-03 (Medium) — `DocumentSearchSpec.sensitivity_threshold` is untyped.** `backend/app/domain/ports.py:327` declares `sensitivity_threshold: Any = "restricted"` (a bare string default, not the `DocumentSensitivity` enum used by `backend/app/domain/document.py:60`). A misconfigured caller can pass an arbitrary object and the adapter decides what it means. Type it as `DocumentSensitivity` (or `str` with validation) and `DocumentSearchHit.snippet` (`backend/app/domain/ports.py:359`, currently `Any`) as `str | dict[str, str]` or similar.
- **T-04 (Low) — break-glass intentionally crosses tenants, and the domain does not record which side owns the decision.** `backend/app/domain/break_glass.py:101-107` documents that the grant belongs to the grantor's tenant while the actor may operate elsewhere. That is the feature's point, but no field distinguishes "grantor tenant" from "target tenant", so a future reader cannot tell from the row alone which tenant's audit chain to consult. Consider an explicit `target_tenant_id: UUID | None` field.

## 3. Audit hash chain (shape PASS — findings A-01…A-06)

The core construction in `backend/app/domain/audit.py:66-76` (`SHA-256(prev_hash + 0x00 + canonical(payload))`), `canonical_json` with `sort_keys=True` (`backend/app/domain/audit.py:43-50`), `GENESIS_HASH` anchor (`backend/app/domain/audit.py:81`), and the `verify_chain` linkage checks (`backend/app/domain/audit.py:340-384`) match AGENTS.md §16.3. Findings are around the contract, not the formula:

- **A-01 (Medium) — `verify_chain` docstring contradicts the implementation.** The docstring (`backend/app/domain/audit.py:357-359`) promises "subsequent rows are still counted so the operator can see how far the corruption extends", but the implementation returns on the *first* mismatch (`backend/app/domain/audit.py:371-382`). `rows_checked` therefore stops at the first bad row. Fix the docstring or continue scanning (collecting all mismatches) to match it.
- **A-02 (Low) — `GENESIS_HASH` docstring contradicts its value.** The module docstring (`backend/app/domain/audit.py:26-28`) says the sentinel is "intentionally non-zero-looking so a 'no chain' bug is detectable", but the value is `"0" * 64` (`backend/app/domain/audit.py:81`) — i.e. maximally zero-looking. Either the value or the rationale is wrong; likely the docstring is stale.
- **A-03 (Medium) — two different canonical-JSON forms exist.** Audit hashing uses `json.dumps(..., default=str)` with default `ensure_ascii=True` (`backend/app/domain/audit.py:50`), while the webhook provenance digest uses `ensure_ascii=False` (`backend/app/domain/webhook_capture.py:127-133`). Two "canonical" forms means the same logical payload hashes differently in different subsystems, and `default=str` silently coerces non-JSON-native types (datetimes, UUIDs, enums) so distinct objects can collide to the same string. Centralise one canonicaliser in the domain and make coercion explicit.
- **A-04 (Low) — empty chain verifies as `ok=True` with `rows_checked=0`.** `verify_chain([])` returns success vacuously. A "verify tenant with no rows" report is indistinguishable from "verify tenant with a healthy chain" unless the caller checks the count. Consider returning a distinct status (or documenting that callers must assert `rows_checked > 0`).
- **A-05 (Medium) — correction payloads bypass the domain error taxonomy.** `make_correction_payload` (`backend/app/domain/audit.py:252-275`) raises bare `ValueError` instead of `ValidationFailed`, unlike every other domain constructor. The HTTP layer's domain-error → structured-response mapping will treat these as 500s rather than 422s. Same class of issue as S-05; fix together.
- **A-06 (Medium) — `AuditEvent` identity fields are `Any`.** `tenant_id`, `actor_id`, `subject_id` (`backend/app/domain/audit.py:291-296`), `case_id` (`...:297`), and `ChainVerificationResult.first_mismatch_id` (`backend/app/domain/audit.py:321`) are typed `Any` with "typed at the boundary" comments. The audit aggregate is the *worst* place for untyped identity: a tenant/actor mix-up here is a security-relevant miscategorisation. Type them `UUID` (as the store Payload section already assumes) and see S-01.

## 4. Strict typing / `Any` (FAIL — findings S-01…S-06)

`backend/pyproject.toml` sets `strict = true` for mypy and AGENTS.md R6 requires "no `Any` outside ports". The domain layer as written cannot satisfy either:

- **S-01 (High) — `Any` is pervasive in domain aggregates, not just ports.** Non-exhaustive list: `Case.data: dict[str, Any]` and `FieldSnapshot.data` (`backend/app/domain/case.py:101,161`); `CaseTypeSchema.rules: tuple[dict[str, Any], ...]` (`backend/app/domain/case_type.py:312`); `WorkflowTransition.guard/actions`, `WorkflowTransitionRecord.payload` (`backend/app/domain/workflow.py:265-266,552`); `SlaClock.breach_action/escalation_*/metadata` (`backend/app/domain/sla.py:156-159`); `QuarantineRecord.context`, `PolicyDecision.context`, `evaluate_row` values (`backend/app/domain/channel.py:309,400,410`); `FormDefinition`/`FormSectionSpec` mappings (`backend/app/domain/form.py:120,141-142,323`); `SavedSearch.query_shape/filters` (`backend/app/domain/saved_search.py:125-127`); `DomainEvent.payload`, `validate_payload` (`backend/app/domain/events.py:286,354,365`); `ExtensionSpec.metadata` (`backend/app/domain/extension.py:227`); rule evaluator internals (`backend/app/domain/rules.py:122,184-185,264-407`); `SearchFilter.value`, `SearchHit.data_snippet` (`backend/app/domain/ports.py:1935,1996`); `Telemetry.event` (`backend/app/domain/ports.py:1141`). JSON-payload `dict[str, Any]` is idiomatic, but then R6 as written is unachievable — either introduce a `JsonValue`/`JsonDict` alias with strict boundaries, or scope R6 explicitly to "no `Any` for identity/timestamps/enums" and enforce *that*.
- **S-02 (High) — timestamps typed as `Any` (or `object`) defeat the clock-purity design.** `Session.created_at/last_used_at/locked_until` and every `now` parameter (`backend/app/domain/session.py:195-198,213-493`), `Role.created_at` / `RoleAssignment.assigned_at` / `make_role(now)` (`backend/app/domain/role.py:70,126,165`), `SavedSearch.created_at` / `create(now)` (`backend/app/domain/saved_search.py:129,148`), `Queue.created_at/updated_at` (`backend/app/domain/queue.py:95-96` — typed `object | None`, worse than `Any`). The `_coerce_datetime` helper (`backend/app/domain/session.py:474-485`) exists precisely because strict checking was surrendered at the boundary. Type all timestamps `datetime` and delete the coercion.
- **S-03 (Medium) — `dict[str, object]` vs `dict[str, Any]` inconsistency.** `Task.outcome: dict[str, object] | None` (`backend/app/domain/task.py:98`), `LegalHold.to_payload() -> dict[str, object]` (`backend/app/domain/legal_hold.py:150`), `OutboundDelivery.payload_json: dict[str, object]` (`backend/app/domain/outbound_webhook.py:350`) vs `dict[str, Any]` everywhere else. Pick one (`Any` with a `JsonValue` alias preferred) and apply uniformly; `object` values force casts on every read.
- **S-04 (Medium) — untyped `**changes: Any` / `**kwargs: dict[str, Any]` bypass the checker at mutation points.** `Case.edit` builds `kwargs: dict[str, Any]` then `replace(self, **kwargs, ...)` (`backend/app/domain/case.py:277-316`); `import_job._replace(job, **changes: Any)` (`backend/app/domain/import_job.py:471`); outbound `_replace`/`_replace_delivery` take `**changes: object` with a dozen `# type: ignore[arg-type]` comments (`backend/app/domain/outbound_webhook.py:257-278,425-444`). A typo'd field name becomes a runtime `TypeError` instead of a mypy error. Prefer explicit `replace(self, title=..., ...)` or typed overloads.
- **S-05 (High) — ~50 `raise ValueError/TypeError` sites bypass the domain error taxonomy.** `document.py` (all invariant checks, e.g. `backend/app/domain/document.py:136-152,220-230,265-279,343-348`), `sla.py` (`backend/app/domain/sla.py:194-414`), `break_glass.py` (`backend/app/domain/break_glass.py:143-174`), `events.py` (`backend/app/domain/events.py:305-328`), `audit.py` correction factory (`backend/app/domain/audit.py:266-270`). The HTTP layer maps *domain* errors to structured responses (`errors.py` taxonomy); stdlib errors risk surfacing as 500s or unhandled branches. Convert to `InvariantViolation`/`ValidationFailed` (the `break_glass` docstring even admits the mapping burden it pushes onto the application layer).
- **S-06 (Medium) — runtime `assert` used for control flow.** `assert spec is not None` appears twice (`backend/app/domain/case_type.py:253,358`). Assertions are stripped under `python -O`, turning a would-be `AttributeError` into silent `None` propagation. Use explicit `if …: raise InvariantViolation`.

## 5. Boundaries & invariants — critical bugs

- **B-01 (Critical) — `SlaClock.resume()` from `WARNING` always raises.** `backend/app/domain/sla.py:255-265`: the `WARNING` branch calls `_pause_duration(self, at)`, which raises `ValueError("paused clock must carry paused_at")` when `paused_at is None` (`backend/app/domain/sla.py:403-415`). A clock in `WARNING` never carries `paused_at` (only `pause()` sets it, and that flips status to `PAUSED`), so resuming a warning-tier clock — a legal, expected operator action — deterministically crashes instead of normalising to `ACTIVE`. Same defect hits legacy `RUNNING` rows: `resume()` on `RUNNING` falls through to the `paused_at is None` guard (`backend/app/domain/sla.py:253-283`) and raises. The `WARNING` branch should not consult pause duration at all (there was no pause); `RUNNING` needs an explicit arm.
- **B-02 (Critical) — two sources of truth for legal hold.** `Case.legal_hold: bool` (`backend/app/domain/case.py:181`) and the `LegalHold` aggregate (`backend/app/domain/legal_hold.py:54-79`) coexist with no documented synchronisation. `Case.change_status` enforces the H0 flag (`backend/app/domain/case.py:344-357`) while the H1 lifecycle (`place`/`release`, `HoldPlaced`/`HoldReleased` audit events) lives on the aggregate. An application path that consults one and writes the other can refuse-or-allow disposition incorrectly in either direction. Decide the authority (recommend: aggregate is authoritative, flag is a cached projection or is removed) and assert consistency at the use-case boundary.
- **B-03 (Critical) — custom reference formats produce references `CaseReference` rejects.** `ReferenceFormat.render` (`backend/app/domain/reference_format.py:115-184`) can emit any template (e.g. `MRN-{YYYY}-{SEQ}`), but `CaseReference.__post_init__` enforces `^C-[A-Z0-9-]{1,16}-\d{4}-\d{6}$` (`backend/app/domain/case.py:51-75`). Any tenant that adopts FM-009 custom formats will fail case creation at the domain constructor. The two modules also disagree on charsets: `_TYPE_KEY_OK` allows only `[A-Z0-9_]` (`backend/app/domain/reference_format.py:205`) while `CaseType.key` allows dashes too (`backend/app/domain/case_type.py:497`); the template docstring advertises `{SEQ:Nd}` (`backend/app/domain/reference_format.py:27`) but the patterns implement `{SEQ:N}` (`backend/app/domain/reference_format.py:78`). Reconcile before FM-009 ships: either version the `CaseReference` grammar per tenant or validate templates against it.

## 6. Boundaries & invariants — high severity

- **H-01 (High) — `ports.py` violates the R2 hard file-size limit.** Measured at **1961 lines** (via line count; the 1000-line hard limit in AGENTS.md §4.R2). It is also the module most in need of splitting (30+ protocols + 8 dataclasses). Recommend splitting by pillar area (cases, documents, workflow/tasks/queues/SLA, audit/outbox, identity/sessions/roles, ingestion/channels, retention/legal-hold, search, webhooks, connectors/coexistence) with `ports.py` re-exporting.
- **H-02 (High) — `ports.py.__all__` omits 17 public names.** Present in module but absent from `__all__` (`backend/app/domain/ports.py:1748-1787`): `SlaClockRepository`, `TaskRepository`, `WorkflowInstanceRepository`, `ParticipantRepository`, `DocumentSearchSpec`, `DocumentSearchHit`, `DocumentSearchResultPage`, `DocumentSearchProvider`, `SearchFilter`, `SearchSpec`, `SearchHit`, `SearchResultPage`, `SearchProvider`, `CaseArchivalRepository`, `DisposalFreezeRepository`, `OrphanCaseProposalRepository`, `CoexistencePolicyRepository`. `from app.domain.ports import *` silently drops the search, task, SLA-instance, participant, archival, freeze, orphan, and coexistence contracts.
- **H-03 (High) — `audit.py.__all__` omits 16 event-type constants + `CorrectionPayload`.** Missing (`backend/app/domain/audit.py:387-417`): `WORKFLOW_TRANSITIONED`, `SLA_WARNING_RAISED`, `QUEUE_DEFINED`, `QUEUE_RECONFIGURED`, `QUEUE_RETIRED`, `TASK_CLAIMED`, `TASK_RELEASED`, `TASK_BULK_HANDLED`, `TASK_DELEGATED`, `CASE_ARCHIVED`, `CASE_UNFROZEN`, `DISPOSAL_FREEZE_DECLARED`, `DISPOSAL_FREEZE_CANCELLED`, `ORPHAN_PROPOSAL_SURFACED`, `ORPHAN_PROPOSAL_DISMISSED`, and the `CorrectionPayload` TypedDict. Star-imports lose most of the P02/P08 event catalog.
- **H-04 (High) — `CapturedEmail` has no validation; its validator is dead code.** The aggregate (`backend/app/domain/email_capture.py:65-94`) defines no `__post_init__` and no factory: empty `message_id`/`sender`/`channel_key`, overlong IDs, and arbitrary `destination` strings (the `"document" | "case_note"` vocabulary is documented but unenforced) all construct successfully. `is_valid_message_id` (`backend/app/domain/email_capture.py:49-62`) has zero call sites. Contrast `CapturedWebhook`, which validates in `__post_init__` and computes its digest in `create` (`backend/app/domain/webhook_capture.py:169-222`). Wire the validator into the aggregate.
- **H-05 (High) — channel policy knobs are dead.** `evaluate_row` (`backend/app/domain/channel.py:410-446`) only enforces `required_fields`; `allowed_classifications`, `max_record_bytes`, `unknown_field_severity`, and `invalid_enum_severity` (all fields of `ValidationPolicy`, `backend/app/domain/channel.py:113-151`) have no code path that reads them. The comment admits classification "is enforced by the document-mapping path", but the remaining three severities are inert configuration that suggests guarantees the platform does not provide. Either implement or remove the fields.
- **H-06 (High) — `ImportJob` docstring/implementation contradictions + bookkeeping bugs.** (a) `FieldMapping` docstring says "an empty target means the value is captured for traceability" (`backend/app/domain/import_job.py:134-136`) but `__post_init__` rejects empty targets (`backend/app/domain/import_job.py:143-144`). (b) `mark_failed` stamps the failure time into `committed_at` (`backend/app/domain/import_job.py:427-432`) — a misnamed field that will confuse every report query. (c) `FAILED → FAILED` is allowed and silently overwrites the reason (no idempotency guard), while `attach_preview` takes an unused `now` and `mark_committed` never checks the commit against the preview it claims to match.
- **H-07 (High) — `Case` creation/edit validation gaps.** (a) `Case.create` accepts `sensitivity` verbatim (`backend/app/domain/case.py:197,223`) — never validated against the ladder, never defaulted from `case_type.sensitivity_default` despite the docstring's "inherited" claim (`backend/app/domain/case.py:168-173`). (b) `title.strip()` is called without a `None`/non-string guard (`backend/app/domain/case.py:200,280`) — `title=None` raises `AttributeError`, not `ValidationFailed`. (c) Schema validation checks only required-field presence and unknown-field rejection (`backend/app/domain/case.py:412-418`); field *types* (integer/date/enum/derived) are never checked, so type-invalid data persists until something downstream chokes. (d) `change_status` contains an unreachable branch: `_ensure_not_terminal` (`backend/app/domain/case.py:339`) already raises for terminal states, so the `both-terminal` guard (`backend/app/domain/case.py:342-343`) is dead code — evidence the transition table was edited without re-verification.
- **H-08 (High) — `Task`/`Document` lifecycle asymmetries.** (a) `Task.priority` is free-form (`backend/app/domain/task.py:91`) while `Case.priority` is validated — inconsistent vocabularies for the same concept. (b) `Task.cancel(reason=...)` discards the reason (`_ = reason`, `backend/app/domain/task.py:210`) and stamps cancellation into `completed_at` (`backend/app/domain/task.py:211-216`), conflating two distinct timestamps; add `cancelled_at/cancelled_by` or stop setting `completed_at` on cancel. (c) `cancel` on a `COMPLETED` task silently no-ops (`backend/app/domain/task.py:208-209`) while `complete` on a `CANCELLED` task raises (`backend/app/domain/task.py:187-188`) — pick one philosophy. (d) `Document` has no `version_token`, unlike `Case`/`Task`/`Queue` — concurrent `with_new_version` calls can interleave without optimistic-concurrency protection.
- **H-09 (High) — frozen aggregates hold caller-owned mutable references (shallow immutability).** `Case.create` stores the caller's `data` dict by reference (`backend/app/domain/case.py:216`); same pattern for `SlaClock` metadata/breach actions (`backend/app/domain/sla.py:199-213`), `QuarantineRecord.context` (`backend/app/domain/channel.py:309`), `SavedSearch.query_shape/filters` (`backend/app/domain/saved_search.py:158-173`), `DomainEvent.payload` (only `webhook_capture.create` copies, `backend/app/domain/webhook_capture.py:217`). A caller that mutates its dict after construction mutates the "immutable" aggregate. Deep- or shallow-copy inbound mappings at construction (at minimum `dict(data)` / `tuple(...)`).
- **H-10 (High) — unbounded global regex cache contradicts the "no module state" contract.** `_PATTERN_CACHE` (`backend/app/domain/rules.py:108`) grows without bound on distinct attacker-influenced patterns (memory exhaustion) and caches compiled patterns forever; the module docstring simultaneously promises "no module state" (`backend/app/domain/rules.py:11-14`). Cap the cache (`functools.lru_cache(maxsize=…)` on a helper) or document the trade-off.
- **H-11 (High) — workflow validator gaps in the domain.** (a) `WorkflowTransition.__post_init__` rejects *all* self-loops (`backend/app/domain/workflow.py:289-290`), but human-driven self-transitions (rework, re-review, "request changes" staying in-state) are legitimate workflow shapes — this forces authors to model no-op states. (b) `JoinSpec` validates `min_completions >= 1` but not `<= len(branches)` (`backend/app/domain/workflow.py:209-215`), despite the module docstring claiming the validator rejects out-of-range values — the domain (the backstop) does not. (c) `WorkflowVersion.draft` checks duplicate *subprocess* keys but not duplicate state/transition keys, exactly-one-initial, or reachability (`backend/app/domain/workflow.py:402-432`) — an invalid machine can exist as a draft and only fails later, if at all.
- **H-12 (High) — `retention.py` exceeds the soft size limit and buries ordering hazards.** Measured at **961 lines** (soft refactor trigger: >600, AGENTS.md §4.R2). `RetentionPolicyStatus` is defined *after* `RetentionPolicy` (`backend/app/domain/retention.py:96-139` vs `:245-250`); same for `ArchivalStatus` after `CaseArchival` (`backend/app/domain/retention.py:568-` vs `:711-`). Forward references work under `from __future__ import annotations`, but the ordering invites circular-maintenance mistakes; move status enums above their aggregates when the file is split. `RetentionPolicy.draft` hardcodes `version_number=1` (`backend/app/domain/retention.py:181`) with versioning delegated to the repository by comment — a second draft for the same target is a silent version collision unless every adapter remembers to bump.
- **H-13 (High) — `OutboundDelivery.record_attempt` does not own the state machine its docstring describes.** The docstring (`backend/app/domain/outbound_webhook.py:381-397`) specifies `PENDING → DEAD_LETTERED` after `MAX_ATTEMPTS`, but the failure path returns `state=self.state, unchanged` (`backend/app/domain/outbound_webhook.py:414-422`) and punts the transition to the caller. The "state machine is enforced by `record_attempt`" claim (also at `backend/app/domain/outbound_webhook.py:95-99`) is false; a caller that forgets the dead-letter step retries forever. Either pass the cap in and enforce, or correct the docstring.
- **H-14 (High) — no timezone discipline on datetime boundaries.** Aggregates accept naive and aware datetimes interchangeably (`Case.created_at`, `SlaClock.started_at/due_at`, `Session` fields via `Any`, retention windows). Mixing them raises `TypeError` at comparison time (`is_overdue`, `is_active_at`, eligibility scans) — a runtime crash on legal inputs. `_coerce_datetime` (`backend/app/domain/session.py:474-485`) accepts naive datetimes silently instead of rejecting them. Enforce tz-aware UTC at construction (fail-closed) since the platform contract is "UTC from `Clock`" (AGENTS.md §16).

## 7. Boundaries & invariants — medium severity

- **M-01 — `events.py` PHI heuristic over-matches and the guard runs twice.** `_key_looks_like_phi` (`backend/app/domain/events.py:281-283`) uses bidirectional substring (`needle in n or n in needle`), so single-character keys (`"e"` matches `"email"`) and innocent keys containing fragments are rejected — false positives that will confuse use-case authors. `validate_payload` then runs the PHI guard twice: once standalone (`backend/app/domain/events.py:311-316`) and again inside the whitelist loop (`backend/app/domain/events.py:327-331`). Keep one pass with word-boundary or token matching.
- **M-02 — two parallel event catalogs can drift.** `EVENT_CATALOG` (8 entries, `backend/app/domain/events.py:224-233`) vs `ALL_EVENT_TYPES` (30+ entries, `backend/app/domain/audit.py:183-218`). No test or code cross-checks that every audit event has a domain-event spec or vice versa. Add a consistency assertion or merge the source of truth.
- **M-03 — `DomainEvent` takes wall-clock time in the domain.** `occurred_at` defaults to `datetime.now(tz=UTC)` (`backend/app/domain/events.py:357`), while `SlaClock.start` deliberately requires timestamps passed in to stay pure (`backend/app/domain/sla.py:177-184`). Make the default explicit (required parameter) for determinism.
- **M-04 — quarantine context denylist is bypassable.** `QuarantineRecord.__post_init__` bans four literal keys (`backend/app/domain/channel.py:320-322`); `values`, `row`, `data`, `fields` and any other payload-shaped key pass through, defeating the Constitution V posture the check claims. Use an allowlist for diagnostic context.
- **M-05 — `Queue` silent dedupe vs fail-fast inconsistency.** `Queue.create`/`set_members` silently drop duplicate member ids (`backend/app/domain/queue.py:138-144,230-236`) while `MappingVersion` rejects duplicate sources (`backend/app/domain/import_job.py:215-218`). Silent dedupe hides caller bugs and shifts `rr_cursor` semantics; reject duplicates. Related: `created_at/updated_at: object | None` (`backend/app/domain/queue.py:95-96`) should be `datetime | None`; `advance_cursor` on `MANUAL` bumps `version_token` for a no-op write (`backend/app/domain/queue.py:259-260`), generating spurious conflicts.
- **M-06 — `SavedSearch` validates less than its docstring claims.** The module docstring promises the entity validates the shape "so the row that lands … is always executable" (`backend/app/domain/saved_search.py:12-19`), but `create` validates only the name (`backend/app/domain/saved_search.py:131-136,140-173`): filter fields/ops, sort-vs-`SORTABLE_FIELDS` coherence, and tenant/owner presence are unchecked. `to_wire` returns raw `UUID`/`datetime` objects, not JSON-native values (`backend/app/domain/saved_search.py:175-192` — only `created_at` is serialised); `SortSpec.from_dict` coerces via `str(...)`, turning missing keys into the literal `"None"` (`backend/app/domain/saved_search.py:83-88`).
- **M-07 — `Participant` tombstone and primary gaps.** `remove()` overwrites `removed_at` unconditionally (`backend/app/domain/participant.py:87-89`) — a double-remove loses the original timestamp; guard or raise. Nothing enforces at-most-one `is_primary` per case (acknowledged as possibly application-owned, but undocumented here). `create` does not check `tenant_id`/`case_id` presence, unlike `Task.create` (`backend/app/domain/task.py:131-132`).
- **M-08 — `CoexistencePolicy.set_migration_state` permits arbitrary jumps.** The docstring lists allowed transitions (`backend/app/domain/coexistence.py:330-341`), but the code only bars leaving terminal states and returning to `UNMIGRATED` (`backend/app/domain/coexistence.py:345-359`) — e.g. `UNMIGRATED → RETIRED_FROM_SOURCE` directly is accepted. No `supersede`/version-bump helper exists although `version` is part of the identity. `provenance_note` is documented as "never carries payload data" with no enforcement.
- **M-09 — `Connector` transition bookkeeping gaps.** `begin_drain(by=...)` ignores the actor (`backend/app/domain/connector.py:357-377`); `confirm_drain` does not stamp `updated_at` (`backend/app/domain/connector.py:379-400`); counter non-negativity is checked in `confirm_drain` but not at construction (`backend/app/domain/connector.py:237-271`); empty `design_summary` is accepted although approvers are expected to read it. `ConnectorKind`/`ConnectorState` use `enum.Enum` while every other module uses `StrEnum` — standardise.
- **M-10 — `BreakGlassGrant.check` misreports not-yet-valid grants.** `now < granted_at` returns `EXPIRED` (`backend/app/domain/break_glass.py:204-205`); add a distinct `NOT_YET_VALID` reason — an operator debugging clock skew will misread the audit row. `is_active` and `check` duplicate the same predicates (`backend/app/domain/break_glass.py:179-216`); funnel one through the other.
- **M-11 — `CaseRelationship` factories validate little.** `make_related_pair/make_split_edge/make_merge_edge` (`backend/app/domain/case_relationship.py:121-222`) do not check `tenant_id`/actor presence, reason/note bounds, or that both cases belong to the same tenant (cross-tenant edges would be a security-relevant mislink). The `relationship_id` guard uses `if not self.relationship_id` (`backend/app/domain/case_relationship.py:103-104`) — always falsy-proof for real UUIDs, so it only catches `None`.
- **M-12 — `rules.py` semantic rough edges.** (a) `in` against a string field is substring matching (`backend/app/domain/rules.py:243-248`) — `"a" in "abc"` authorises; document or restrict to collections. (b) `_ordering` rejects booleans but `eq`/`ne` accept them (`backend/app/domain/rules.py:372-390` vs `:238-241`) — inconsistent. (c) Depth guard is `_depth > _MAX` (`backend/app/domain/rules.py:209`), permitting one level more than the publish-time validator clients will assume; align exactly. (d) `RuleEvaluationError` subclasses `ValidationFailed`, so a malformed guard on an already-*published* version surfaces as HTTP 422 (client error) rather than 500 (authoring/operator bug) — consider a distinct internal error for runtime-malformed conditions. (e) `evaluate` re-normalises at every recursion level (`backend/app/domain/rules.py:214` + `_all/_any/_not_operand`); normalise once at entry.
- **M-13 — `CaseType` version-promotion timestamp hazard.** `with_published_version` copies `version.published_at` into `updated_at` (`backend/app/domain/case_type.py:537-541`, same shape in `backend/app/domain/workflow.py:370-374`), but `published_at` is `datetime | None` — a version constructed without publish metadata would null out `updated_at`. Assert non-`None` or fall back to the promotion time. Also `_validate_label_history` checks ordering/uniqueness but not that the latest entry equals the field's current label (`backend/app/domain/case_type.py:279-287`).
- **M-14 — `FormBinding` lifecycle is a second, weaker shape.** Draft/published is tracked via `published_at is None` (`backend/app/domain/form.py:299-367`) instead of a status enum like `FormVersion`/`CaseTypeVersion`/`WorkflowVersion`, and there is no retire path. `_collect_referenced` silently stops at the depth cap (`backend/app/domain/form.py:498-508`) while `_check_condition` raises at the same cap (`backend/app/domain/form.py:406-442`) — inconsistent failure modes. `FormFieldSpec` has no `__post_init__` (empty keys/labels construct fine; only section/duplicate checks in `_validate_definition` catch part of it). `apply_hidden_field_preservation` preserves hidden values but never evicts stored keys for fields deleted from the form — stale data accumulates.
- **M-15 — form operator set is narrower than the rule language without a stated reason.** Forms allow only `eq/ne/in/exists/truthy` (`backend/app/domain/form.py:78`) while `rules.py` supports the full catalog including `all/any/not` and ordering. Authors cannot express "show when A and B". If intentional (v1 scope), say so and point at P02; if not, unify on `rules.evaluate`.
- **M-16 — `reference_format` validation/render mismatches.** Lowercase tokens (`{tenant}`) match neither `_TOKEN_PATTERN` (`backend/app/domain/reference_format.py:80`) nor the known-token set, so `validate_template` *passes* them and `render` leaves them as literals — a template can validate yet emit garbage. Fix by rejecting any `{...}` segment that is not a known token (case-insensitively or explicitly).
- **M-17 — `RetentionPolicy.publish/retire` idempotency asymmetry.** `publish` on an already-published policy returns `self` (`backend/app/domain/retention.py:199-200`) but `retire` on a draft raises (`backend/app/domain/retention.py:222-223`) while `retire` on retired returns `self` (`backend/app/domain/retention.py:220-221`). Standardise (idempotent everywhere or strict everywhere) and document the choice; mixed semantics cause double-submit bugs.
- **M-18 — `DispositionRequest.approve` silently drops empty reasons** (`(reason or "").strip() or None`, `backend/app/domain/retention.py:394-400`) while `reject` requires one — fine as policy, but the asymmetry should be a stated decision (approvals without rationale weaken the "every state change carries the why" posture in `CaseArchival.archive`, which *requires* reasons).
- **M-19 — undocumented Protocol members.** `OutboxRecord` is an empty Protocol (`backend/app/domain/ports.py:1039-1040`); `OutboxWriter.enqueue`, `DocumentStore.put/get`, `MessageBus.publish`, `Telemetry.event` carry no docstrings, violating the R4 "every public function/class/protocol needs a docstring" rule the rest of the layer follows well.
- **M-20 — `WebhookSubscription` mutation helpers bypass validation.** `disable/retire/bump_version` use a hand-rolled `_replace` that re-enumerates every field (`backend/app/domain/outbound_webhook.py:257-278`) instead of `dataclasses.replace`, with per-line `# type: ignore[arg-type]`. Any future field added to the dataclass is silently dropped by these transitions. Delete the helper and use `dataclasses.replace`.

## 8. Low-severity / hygiene notes

- **L-01** — `HoldNotPresent` subclasses `Conflict` (HTTP 409) for "no hold to release" (`backend/app/domain/legal_hold.py:191-204`). Defensible (distinguishes from 404), but it stretches `Conflict` semantics; ensure the API docs call this out.
- **L-02** — `LegalHold.place`/`release` presence checks use `if not <UUID>` (`backend/app/domain/legal_hold.py:98,130-131`), which is always truthy for real UUIDs and only catches `None`. Explicit `is None` checks read better and survive exotic ID types.
- **L-03** — `SlaClock.complete`/`mark_breached`/`mark_warning` accept `at` and ignore it (`_ = at`, `backend/app/domain/sla.py:308,330,352`). Combined with H-14-adjacent concerns: breached/completed clocks carry no timestamp on the aggregate — timeline rendering depends entirely on the audit row existing. Either store the timestamp or remove the parameter.
- **L-04** — `Task.cancel` on non-`OPEN` returns `self` including for `COMPLETED` (see H-08c); `SlaClock.pause` on `PAUSED` returns `self`; `RetentionPolicy` transitions are mixed (M-17). Audit the whole layer once for a single idempotency philosophy and state it in one place.
- **L-05** — `extension.py` validation reports only the first failure (`_require` raises immediately, `backend/app/domain/extension.py:235-237`). Aggregated errors would improve the admin UX for module registration; also `_specs_equal` excludes `metadata` from idempotency comparison (`backend/app/domain/extension.py:505-538`) — two registrations differing only in metadata are "equal", which should be stated, not implied.
- **L-06** — `ExtensionSpec.registered_at: _UUID | None` and `tenant_id: _UUID | None` (`backend/app/domain/extension.py:225-226`): the field name says timestamp, the type says UUID; the `_UUID` alias import style is used nowhere else. Rename/retype.
- **L-07** — `CapturedWebhook.create` shallow-copies payload (`dict(payload)`, `backend/app/domain/webhook_capture.py:217`); nested structures remain shared (see H-09). The full payload is stored on the row (`backend/app/domain/webhook_capture.py:163`) — confirm this is consistent with the quarantine redaction posture, since webhook payloads may carry sensitive fields.
- **L-08** — `is_valid_webhook_id` rejects spaces/control chars (`backend/app/domain/webhook_capture.py:96-111`); RFC 7230 allows spaces in header values, so over-strict producers could see spurious 422s. Confirm against the actual gateway's behaviour.
