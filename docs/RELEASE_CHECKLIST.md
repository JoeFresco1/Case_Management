## Required follow-ups before merge

These are the minimal mechanical fixes that flip every AC green.

### 1. Starlette deprecation (blocks collection of `tests/interfaces/test_cases_router.py`)

22 occurrences of `status.HTTP_422_UNPROCESSABLE_ENTITY` across 8 router files. Rename to `status.HTTP_422_UNPROCESSABLE_CONTENT`. The current starlette version emits a `StarletteDeprecationWarning` which pytest-asyncio promotes to an error because of `filterwarnings = ["error"]` (`pyproject.toml:74`). Affects AC-001 collection, AC-005 indirectly.

Files: `app/interfaces/http/routers/{cases,capture,audit,documents,security,exports,webhooks}.py`.

### 2. ruff — `--fix` the auto-fixable subset

Run `uv run ruff check --fix .` then `uv run ruff format .`. The remaining manual fixes:
- `F821`×14 — undefined-name errors (likely missing imports in `tests/webhooks/test_outbound.py` and similar; the test file has duplicate local imports flagged as `PLC0415`×64)
- `PLW0603`×12 — global-keyword usage that should be refactored to arguments or instance state
- `ARG001`×5 — unused function arguments in fixtures/tests
- `N806`/`N818` — variable naming conventions
- `DTZ003`×4 — `datetime.now()` calls in tested code that need explicit UTC

### 3. mypy — add `explicit_package_bases = true` + `uuid_extensions` stubs

### 4. import-linter — restore layer purity

Two structural classes of violation:

**(a) `app.domain` reaches `app.infrastructure` via `app.deps`**
`app/domain/ports.py:40` imports `app.deps`, which imports `fastapi`/`sqlalchemy`/`infrastructure`. The fix: `ports.py` should not import `app.deps`; the Protocol-typed factories belong in `ports.py` itself, and any FastAPI-typed factories live in `app/deps.py` (interfaces layer). This is the canonical seam described in `AGENTS.md §12` and `tasks.md T008`.

**(b) Routers import `infrastructure.persistence.*` directly**
~25 router files import `app.infrastructure.persistence.{models,repositories,audit_outbox}` and `app.infrastructure.storage.local_document_store`. Per `AGENTS.md §10` and the import-linter contract, routers (interfaces) must depend on application use-cases only. Introduce thin application-layer façade modules (e.g. `app/application/cases/repository_facade.py`) that expose the repository operations the routers need; have routers depend on those. Same fix for `app/infrastructure/messaging/outbox_dispatcher.py` (used by `app/interfaces/http/routers/admin_outbox.py`) and `app/infrastructure/telemetry/correlation.py` (used via `app.deps`).

A workable one-shot mitigation: add `app.deps`, `app.db`, `app.infrastructure.persistence.audit_outbox`, `app.infrastructure.persistence.repositories`, `app.infrastructure.persistence.models`, `app.infrastructure.persistence.documents`, `app.infrastructure.storage.local_document_store`, `app.infrastructure.messaging.outbox_dispatcher`, `app.infrastructure.telemetry.correlation`, `app.infrastructure.secrets.local_secret_provider`, `app.infrastructure.persistence.search.sql_search_provider` to the `forbidden_modules` list as **exceptions** in `[tool.importlinter]`, but that re-introduces the layering violation this contract was created to prevent. **Recommended: do the refactor.**
